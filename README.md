# Бағдар

Персональный маршрут поступления для учеников 10–11 класса Казахстана.
Путь построен как линия метро: **Начало → Анкета → Диагностика → Рекомендации → Сравнение → Маршрут**. На каждом экране видно, где вы находитесь, что пройдено и что дальше.

**Демо:** https://bagdar-tau.vercel.app

Правила проекта и контракты — в [CLAUDE.md](CLAUDE.md).

## Задача и решение

**Задача (кейс 02 LOCUS):** абитуриенту нужен не ещё один список вузов, а маршрут: куда поступать, почему именно туда и что сделать следующим шагом.

**Решение:** «Бағдар» — маршрут поступления в виде линии метро. Короткая анкета → детерминированный движок правил → рекомендации с причинами → сравнение по приоритетам пользователя → план подготовки по месяцам с одним крупным «следующим шагом».

```
анкета (Profile) ──► движок правил src/engine ──► Recommendation[] + reasons[] ──► UI
                                                         │
                                                         └──► /api/explain (LLM) — только пересказ reasons[]
```

### Что отличает продукт
- **Живая выдача.** Бюджет, страна, главный интерес и экзамены меняются прямо на экране рекомендаций. Подборка пересчитывается мгновенно, изменившиеся карточки подсвечиваются, а баннер сообщает, *что именно* поменялось: «появились: AlmaU, КИМЭП · ушли из топа: КазНУ».
- **Прозрачный отсев.** Строка «Скрыто 12 вариантов: дорого — 3 / не та страна — 7 / не хватает экзамена — 2»: у каждой скрытой программы ровно одна причина, так что сумма сходится.
- **План как схема метро.** Шаги сгруппированы по месяцам, у каждого типа шага свой цвет линии (экзамен, учёба, документы, срок, активность). Просроченные честно отмечены красным, шаги без даты помечены «уточнить на сайте».
- **Календарь в один клик.** Экспорт `.ics` собирается прямо в браузере и включает только шаги с подтверждённой датой; напоминание приходит за 7 дней.

## Тестовый сценарий для жюри

1. Откройте демо → «Начать маршрут» → «Заполнить примером» → «Показать рекомендации».
2. Диагностика: сильные стороны, ограничения, цель → «Дальше».
3. Рекомендации: у каждой карточки есть шанс (высокий, средний или низкий, без процентов), причины, стоимость и источник.
4. **Сдвиньте бюджет на «только грант»** — карточки подсветятся, и баннер покажет, что изменилось. Затем смените главный интерес, добавьте страну или экзамен.
5. Отметьте две программы «В сравнение» → «Дальше»: сравнение по вашим приоритетам.
6. Маршрут: крупный блок «Следующая станция» → «Готово, дальше», и прогресс растёт. Перезагрузите страницу — прогресс на месте.
7. «Добавить в календарь (.ics)» — в календарь попадут только шаги с реальной датой.
8. Откройте `/results` в приватном окне: вместо тупика экран предложит заполнить анкету.

## Роли команды

- **A — данные и движок:** `src/data`, `src/engine`, юнит-тесты движка.
- **B — дизайн-система и экраны пути:** `src/components/ui`, `src/styles`, `/start`, `/profile`, `/diagnosis`.
- **C — результат, состояние и AI:** `/results`, `/compare`, `/roadmap`, `src/store`, `src/app/api`, README.
- **Лид:** контракты `src/types`, `src/lib/flow.ts`, e2e, CI.

## Готовые компоненты

Сторонних UI-китов нет: все компоненты (`Card`, `Button`, `Choice`, `MetroLine`, `ProgramCard` и т. д.) написаны командой в `src/components/ui` на Tailwind. Экспорт `.ics` сделан вручную по RFC 5545, без библиотек.

## Известные ограничения

- **Демо-данные.** Часть полей у зарубежных программ не сверена; интерфейс показывает бейдж «демо-данные» на каждом таком поле.
- **Фокус на Казахстане.** Аудитория — 10–11 класс, бакалавриат; зарубежных направлений несколько.
- **Нет процентов шансов.** Честно посчитать вероятность поступления без данных о конкурсе невозможно, поэтому шанс показан как высокий / средний / низкий с объяснением.
- **Нет бэкенда.** Прогресс хранится в localStorage и привязан к устройству.


## Архитектура

```
src/
  types/index.ts               общие контракты          — правит только лид
  lib/flow.ts                  порядок станций маршрута — правит только лид
  app/layout.tsx               корневой layout          — лид
  app/page.tsx                 redirect на /start       — лид
  app/(flow)/layout.tsx        оболочка пути            — лид
  app/(flow)/start|profile|diagnosis/    экраны         — зона B
  app/(flow)/results|compare|roadmap/    экраны         — зона C
  app/api/                     server routes            — зона C
  components/ui/               дизайн-система           — зона B
  styles/tokens.css            токены                   — зона B
  data/                        программы + доступ       — зона A
  engine/                      движок подбора           — зона A
  store/useJourney.ts          состояние + persist      — зона C
e2e/                           сквозные тесты           — лид
```

Ключевое разделение: **решение принимает движок, не LLM**. `src/engine` — чистые функции без сети и случайности, они возвращают `Recommendation[]` с готовыми `reasons[]`. Языковая модель в `src/app/api` только переформулирует эти причины человеческим языком и не может добавить вуз, требование или дедлайн.

Рекомендации и маршрут не лежат в store — они каждый раз вычисляются из профиля. В localStorage попадают только профиль, выбор пользователя и отметки о выполненных шагах.

## Данные и честность фактов

У каждой программы есть `sourceUrl` и `checkedAt`. Поля, под которые источника пока нет, перечислены в `unverified`, и интерфейс ставит бейдж «демо-данные» точечно на них, а не на всю карточку: у одной программы стоимость может быть сверена с официальным прайсом, а требование к среднему баллу — нет.

Неизвестный дедлайн хранится как `null` и выводится как «уточнить на сайте» — выдуманных дат в продукте нет.

Отдельный случай — стоимость. Вузы Казахстана публикуют цену за кредит ECTS, а не за учебный год. Там, где годовая сумма получена пересчётом (60 кредитов = год), об этом сказано в `tuitionNote`, и UI обязан показать эту строку рядом с цифрой: иначе пересчёт выглядит цитатой из прайса.

Шансы поступления показываются как `high / medium / low` с объяснением. Процентов и гарантий нет: их невозможно посчитать честно.

Поля `prestige` и `career` — редакционные оценки, а не факты из источника, поэтому шкала у них такая же грубая. Точное число вроде места в рейтинге выглядело бы проверенным фактом, которым эта оценка не является. `null` означает «не оценивали», а не «плохо».

## Что готово

Путь проходится целиком: анкета собирает профиль, движок считает диагностику, подбор, сравнение и план подготовки. Каталог — 18 программ в шести странах.

**Стоимость сверена с официальными источниками у всех восьми казахстанских программ.** Что сверить не удалось — честно перечислено в `unverified`, и интерфейс ставит на эти поля бейдж.

На входе в анкету есть кнопка «заполнить примером»: без неё посмотреть продукт за минуту невозможно, а заполнять анкету руками ради демонстрации никто не станет.

Проверки: 88 юнит-тестов движка и каталога, 4 сквозных теста на ширине 375px, `typecheck`, `lint`, `build`. Всё это гоняется в CI на каждый пуш.

## AI: где он работает и где не работает

Языковая модель вызывается ровно в одном месте — `src/app/api/explain`. Она получает готовый разбор от движка и пересказывает его человеческим языком. Она **не выбирает программы, не придумывает требования и не считает шансы**: всё это делает детерминированный движок, и заменить его модель не может по устройству кода.

**Провайдеры — только бесплатные в приоритете.** Роут пробует их по очереди: Google Gemini (`gemini-2.5-flash`, бесплатный тариф AI Studio) → Groq (`llama-3.3-70b-versatile`, бесплатный тариф) → OpenRouter (`:free`-модели) → Claude Haiku 4.5 (платный, запасной). Если провайдер упал или упёрся в бесплатный лимит, запрос уходит к следующему. На всю цепочку — общий таймаут 8 секунд. Все вызовы идут через `fetch`, новых зависимостей нет; модели переопределяются через `*_MODEL` в env. Ключ читается только на сервере. Без ключа, при ошибке API или если в ответе окажутся проценты либо обещания, роут возвращает `{ ok: false }`, а интерфейс честно пишет, что пересказ недоступен. Разбор движка при этом остаётся на экране целиком — на это есть отдельный сквозной тест.

Роут публичный, поэтому на вход стоят жёсткие потолки: максимум три программы, шесть причин на программу, 200 символов на причину. Без них эндпоинт можно было бы использовать как бесплатную языковую модель.
